# 家教信息筛选排序系统 — 规格

版本 2.0（重建版）。本文是系统行为的唯一权威描述；实现与本文冲突时，改实现或改本文，二者必居其一。

## 1. 系统做什么

使用者是一位家教老师，定期收到一批家教信息（微信群消息整理成文本）。系统回答一个问题：**这批信息里，哪些单子值得先看？**

流程：读取三个数据文件 → 剔除含屏蔽词的信息 → 按「个人信息」匹配度从高到低排序 → 结果写入 `res.txt` 并展示。

三个使用入口，共享同一套核心逻辑：

| 入口 | 命令 | 说明 |
|------|------|------|
| 命令行 | `python -m tutorfilter` | 跑流水线，打印摘要，写 `res.txt` |
| Web | `python web/server.py` → http://127.0.0.1:8000 | 跑流水线 + 在线管理数据文件 |
| Android | Briefcase 打包的 `tutorfilter` 应用 | 同 Web，本地数据 |

## 2. 数据文件格式（全部 UTF-8，与 v1 完全兼容）

数据目录默认为项目根的 `data/`（CLI 与服务端可用参数改指他处）。

### `Blocked_words.txt` — 屏蔽词

每行一个或多个词，以中文顿号 `、` 分隔：

```
英语、语文
女大学生、92老师
研究生、专职老师
```

解析规则：按行读入 → 去首尾空白 → 按 `、` 切分 → 丢弃空片段。空行与行尾多余的 `、` 不产生空屏蔽词（空字符串是任何文本的子串，会误杀全部数据）。

### `Personal_info.txt` — 个人匹配条件

每行一条 `键：值`（全角冒号），值是备选词列表，以 `、` 分隔：

```
地址：霞山、城市假日
年级：五年级、六年级、初一、初二、初三、高一、高二
科目：数学、物理
时薪：65/小时、70/小时、65/h、70/h
```

解析规则：取**第一个**全角冒号前的部分为键，其后全部为值（值里再出现冒号不切分）；值按 `、` 切分为备选词，去空白、丢弃空片段。无冒号或空键的行跳过。

### `Tutor_info.txt` — 家教信息源

每条信息是一个段落，段落之间以**空行**分隔：

```
【编号】8223
【地址】天河区华景新天地
【年级】五年级
【科目】数学

【编号】8224
【地址】番禺区祈福新村
【年级】初三
【科目】物理
```

解析规则：CRLF 归一为 LF → 按连续空行切段 → 每段去首尾空白 → 丢弃空段。

### `res.txt` — 输出

排序结果，每条前缀 `===== 第 N 个 =====`，条与条之间空一行。由系统生成，覆盖写。

## 3. 筛选与排序语义

### 3.1 过滤

一条家教信息只要包含**任意一个**屏蔽词（子串匹配），整条剔除。屏蔽词表为空时全部保留。

### 3.2 匹配度（v2 修正，v1 的实际缺陷见 §6）

对每条通过过滤的信息，逐个键计算：

> **键匹配** ⇔ 该键的**任意一个**备选词是信息的子串。

**匹配度 = 匹配的键的个数**（上例中满分为 4：地址、年级、科目、时薪）。

### 3.3 排序

按匹配度**降序**；同分保持原文件中的先后顺序（稳定排序）。

> **v1 → v2 语义修正**：v1（`teach.py:sorted_tutors`）把整条值串（如「五年级、六年级、初一、…」）当子串去匹配，该串几乎不可能出现在任何一条信息里，导致绝大多数条目得分为 0，排序实际失效。v2 改为按备选词匹配。数据文件格式不变，用户的现有数据无需任何改动。

## 4. Web API（与 v1 相同的四个端点）

服务端仅用 Python 标准库，监听 `127.0.0.1:8000`。

| 方法 | 路径 | 参数 | 成功响应 |
|------|------|------|----------|
| GET | `/` | — | `index.html` |
| GET | `/api/view` | `?file=文件名` | `{ok, file, content}` |
| POST | `/api/reset` | `{file}` | `{ok, msg}` |
| POST | `/api/append` | `{file, content}` | `{ok, msg}` |
| POST | `/api/run` | — | `{ok, total, filtered_out, kept, personal, results: [{entry, score, matched}]}` |

`run` 响应中：`personal` 是完整的「键 → 备选词列表」映射（前端据此绘制键位标记与高亮备选词），`results` 每条附带结构化匹配信息（`matched` 为命中的键名列表）。

错误：非法文件名 400；文件不存在 404；JSON 解析失败 400；流水线异常 500。文件名白名单：上表四个文件，杜绝路径穿越。

## 5. 非目标

- 不做多用户、鉴权、数据库：单机单人工具。
- 不做模糊匹配/拼音/同义词：精确子串已是该场景的真实需求。
- 不引入 Web 框架：零第三方依赖是本项目的明确约束（Android 端因 Briefcase 除外）。

## 6. v1 已知缺陷清单（重建时修复）

| # | 缺陷 | 位置 | 修复 |
|---|------|------|------|
| 1 | 匹配度用整条值串做子串，排序失效 | `teach.py:sorted_tutors` | §3.2 按备选词匹配 |
| 2 | 屏蔽词切分可产生空串，空串匹配一切 | `teach.py:read_txt` | 解析时丢弃空片段 |
| 3 | 文件缺失时 `read_txt` 返回 `None`，调用方解包即崩 | `teach.py` | 缺文件抛带文件名的明确异常 |
| 4 | 无任何测试 | — | `tests/` 覆盖全部解析/过滤/排序规则 |
| 5 | CLI 的编号菜单交互笨拙（0/1/3/finish） | `teach.py:__main__` | CLI 只做一件事：跑流水线；编辑文件交给编辑器或 Web 界面 |
| 6 | Android 构建产物 275MB 混在源码树 | `android/build/` | 未被 git 跟踪；不入库，可随时删除重生成 |
